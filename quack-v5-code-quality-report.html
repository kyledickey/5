One-line verdict A thoughtfully designed moderation core with a genuinely good durable-work-queue model, undermined at the surface by machine-generated comment noise, reflexive nil checks, a flat 87-file core package, and several places where the "ports and adapters" story is not actually true in the import graph.

2. Architecture overview

The process is one binary. internal/runtime.Run is the composition root: it loads config, opens MySQL and Redis, runs schema reconciliation, builds the Discord session, composes optional modules, registers commands and gateway handlers, starts core workers and the action queue, then serves HTTP until cancelled. Shutdown runs in reverse with a bounded deadline. There is no init() and no mutable package globals beyond compiled regexes and Redis Lua scripts.

What is good

  • Explicit composition. Every dependency is passed by hand in runtime.go. Shutdown order is explicit and each stage is bounded by a context deadline.
  • Consumer-side ports. quack/ports.go declares small interfaces per service (CaseRepository, ActionRepository, and so on). Tests fake them by embedding quack.Repository in a struct and overriding one method.
  • Durable work model. Persisted action rows are the truth; the in-memory queue is only a latency optimisation. Leases fence stale workers. An expired lease is treated as "outcome unknown" and routed to staff review rather than blindly retried.
  • Audit immutability. A GORM callback rejects any update or delete against audit_log_entries.
  • HTTP platform. CSRF double-submit, strict CORS, trusted-proxy handling, body limits, structured error envelope, and log redaction are all present and tested.
  • Small files. Nothing exceeds 504 lines; most files are under 200.

HIGHThe core is not transport-free

internal/quack/guild_lifecycle.go imports discordgo directly. internal/quack/model/schema.go carries gorm:"column:status" on Case.Validity, and model/case_publication.go has eight GORM tags plus a TableName(). The file headers say "domain models remain storage-agnostic". They do not.

HIGHTwo structs per table, kept in sync by hand

store queries pass domain structs like model.Case straight into GORM (tx.Select("*").Create(&caseModel), Model(&model.Case{})) and rely on default snake-case naming to hit the cases table. Meanwhile store/schema_records.go declares a parallel CaseRecord with full column tags that is used only for AutoMigrate. Any field added to one and not the other silently produces a column mismatch at runtime.

MEDModules are not isolated

modules/tickets, modules/honeypot, and modules/generallogging each own a GORM store and a gin routes.go. tickets/components.go imports discordbot/interactions and discordbot/ui. The package doc for modules calls it "the isolation boundary shared by optional modules", but the modules depend on every framework the core is supposed to hide.

MEDmoduleintegration is a second composition root that also holds business logic

60 files. It imports store, all of httpapi/*, all of discordbot/*, quack, and the three modules. It also reaches back and mutates the core: services.Settings.WithModuleEnablementValidator(runtime) is called from moduleintegration.New.

LOWRepository is a god interface

quack.Repository embeds 11 ports and then appends 12 loose methods for OAuth state, sessions, Redis hash get/set, and pings. None of those are moderation concerns. Each embedded port also re-declares CreateAuditLogEntry and GetGuildSettings, so interface segregation was achieved by copy-paste rather than by a shared AuditWriter port.

repeated validationfragile mechanism
  • Guild context and permission are checked in createWithAttribution, again in preflightCreate, and again in create.
  • Idempotency lookup happens twice with subtly different rules. The outer one tolerates existing.TemplateID == nil; the inner one rejects it. The inner lookup (inside the lock) is the one that matters; the outer one is an optimisation that has drifted.
  • Template load and level selection happen twice (preflight, then inside the lock) by design, to detect staleness. That is reasonable, but the comparison logic is spread across two functions and a sentinel error.
  • transactionalService := *s shallow-copies the whole service struct to swap the store. It works today. It breaks silently the day a mutex, cache, or non-copyable field is added to CaseService.
  • Latent invariant. create sets Position: 0 on every action execution, and store.CreateCase derives the unique idempotency key from position. Template validation currently caps levels at one action so this never collides, but the store does not defend itself.

Why this is good The queue is explicitly allowed to drop work because the poller will find it again. Lease expiry does not imply Discord failed, so unsafe or irreversible actions are parked for a human instead of being re-sent. Reversals require a fresh live authorization check at execution time, not at request time.
  • Minor: actionWorkerID() is only action-worker:<unixnano>. No host or PID. The lease token is the real fence, so this is cosmetic, but it makes attempt logs ambiguous across replicas.
  • Minor: the handler map still registers ActionSendDM although the docs state member DMs are no longer an action type.

7. The doc comment problem

Roughly 240 doc comments match a dozen template phrases. They restate the identifier in more words, and in several cases they are copied from an unrelated function and are simply wrong. This directly violates the repo's own AGENTS.md ("Avoid comments that merely restate the identifier").

Why it matters A reader cannot tell at a glance which comments are trustworthy. The hand-written comments in store/action_claims.go, workqueue/queue.go, and runtime/ explain real invariants and are excellent. The generated ones bury them. Because every one of the twelve patterns is greppable, this is a mechanical fix.

8. Style, idiom, and hygiene

MEDReflexive nil-receiver guards
func (s *CaseService) Void(...) {
    if s == nil || s.store == nil {
        return nil, errors.New("case service is not configured")
    }

149 if s == nil guards and 189 "is not configured / not connected" strings. A nil receiver is never a valid state after a constructor. This adds three lines to every method, obscures real preconditions, and makes coverage look more defensive than it is.

MEDProbable data race in the interaction dispatcher
func (d *Dispatcher) Handle(session *discordgo.Session, interaction *discordgo.InteractionCreate) {
    if d.Client == nil {
        d.Client = sessionClient{session: session}   // unguarded write
    }

discordgo runs each handler on its own goroutine by default. Two concurrent first interactions race on this write. The neighbouring Deduper field is correctly guarded by dedupeMu; Client is not. CI does not run with -race.

MEDErrors doubling as UI copy

30 ST1005 hits. Some are simply capitalised; others are Discord-facing sentences passed through error, for example errors.New("Select a server message to create a case."). Error values and user-visible strings are conflated, which makes both harder to change.

LOWPositional-argument overload

35 functions take six or more parameters. The audit helpers take seven or eight positional strings in a row: audit(ctx, guildContext, action, resourceType, resourceID, result, failure). An AuditEvent struct would remove a whole class of argument-order mistakes.

LOWDead code and deprecated APIs
  • Unused: commands.caseMember, commands.embedFields, quack.authorizationSource, quack.levelActionResponses, and the empty testutil.SetTestConfig.
  • 11 uses of deprecated discordgo fields (DMPermission, PermissionManageServer).
LOWSmall duplications and inconsistencies
  • marshalJSONObject (store) and mustMarshalJSONObject (quack) are the same function. truncateRunes (quack) and ui.TruncateRunes likewise.
  • Ten type aliases at the top of store/cases.go re-export model types, each with an identical 20-word comment. Callers could use model.X directly.
  • Struct literals switch mid-literal from one-field-per-line to four fields jammed on one line (routes/cases.go, createCase).
  • 300-character single-line conditions in views/ and dispatcher.taskError.
  • 36 gin.H{...} response envelopes and @Success 201 {object} map[string]interface{} annotations make the generated OpenAPI contract untyped.
  • PermissionBitsString uses fmt.Sprintf("%d") where strconv.FormatUint is idiomatic.
  • ui.Context embeds context.Context and is named ctx by convention, so handlers juggle ctx.Context, ctx.Services, and a separate taskCtx.
  • 21 *JSON string fields on domain models and 115 map[string]any uses: metadata flows through the core stringly typed.
  • httpapi.Run returning is the only thing that ends the process. A dead Discord session does not.
  • store.appendCaseEvent silently returns nil when the case row is missing.

Strengths. Tests are behaviour-named and scenario-shaped (TestAppealQueueConfigurationTakesEffectWithoutRestart, TestCoreWorkersRunAndCancelWithoutOptionalModules). Fakes are built idiomatically by embedding quack.Repository and overriding one method. Security contract tests in httpapi assert redaction, CSRF, CORS, and proxy trust explicitly.

Gaps.

  • httpapi/middleware owns session refresh, cookie expiry, and CSRF token issuance, and has no tests at all. Its behaviour is only exercised indirectly through the platform tests.
  • Unit tests run on SQLite in memory, where SELECT … FOR UPDATE is a no-op and GET_LOCK does not exist. The guild case lock, lease claims, and migration lock are only verified by the five MySQL-gated tests.
  • The GitHub workflow provisions no MySQL service, so those five tests always skip in CI. The concurrency guarantees the architecture depends on are not verified by CI.
  • CI runs go build and go test only. No go vet, no staticcheck, no -race.
  • Zero t.Parallel. Package-level test time is fine today (store 3.3s, quack 2.9s) but it will not stay that way.

11. Recommendations, in priority order

  1. Strip or rewrite the templated doc comments. The twelve phrase patterns are greppable. Keep every comment that explains an invariant; delete every one that restates the name.
  2. Delete nil-receiver guards. Assert required dependencies once in each constructor and let a nil receiver panic like everywhere else in Go.
  3. Collapse the case-creation path. One validation pass, one idempotency rule, and an explicit transactional receiver instead of transactionalService := *s.
  4. Fix the Dispatcher.Client race, then add -race, go vet, staticcheck, and a MySQL service container to the workflow so the gated tests run.
  5. Pick one schema mechanism. Either the checksum ledger or startup AutoMigrate, not both. Either stop passing domain structs to GORM or drop the parallel *Record types. Move migration checksums off embedded Go source.
  6. Split quack by aggregate or, at minimum, move OAuth, session, and Redis-hash methods out of Repository and introduce a shared AuditWriter port.
  7. Push discordgo, gorm, and gin out of quack, model, and modules. Have apierror import idutil instead of the whole core.
  8. Replace 7- and 8-argument audit helpers with an event struct; migrate deprecated discordgo fields; delete the four dead functions and SetTestConfig.
  9. Add tests for httpapi/middleware and separate user-facing Discord copy from error values.
